# 🎯 Desafío: Reto Intermedio 30: Manejador de Historial (Undo)

### 📝 Descripción del Reto
Implementa un sistema de historial (como el de un editor de texto) con tres operaciones:
- **add(accion)**: registra una acción nueva. Si había acciones en redo, se descartan
- **undo()**: deshace la última acción y la mueve a la pila de redo. Devuelve el estado actual
- **redo()**: rehace la última acción deshecha. Devuelve el estado actual

**¿Por qué importa?** Casi todos los editores de texto, IDEs, herramientas de diseño (Photoshop, Figma) y terminales implementan undo/redo. Es un patrón fundamental en UX y en la gestión de estado de aplicaciones.

**Habilidades que practica:** Uso de pilas (stacks), gestión de estado, patrón Command.

### 📊 Posibles enfoques

| Enfoque | Descripción | Complejidad Temporal | Complejidad Espacial |
|---------|-------------|---------------------|---------------------|
| Dos pilas | Pila de acciones y pila de deshechas | O(1) por operación | O(n) |
| Array con índice | Array + puntero de posición actual | O(1) add/undo/redo | O(n) |
| Lista circular | Buffer circular con capacidad fija | O(1) | O(k) k=capacidad |

### 🌍 Dónde se usa
1. **Editores de texto**: Ctrl+Z / Ctrl+Y en VS Code, Word, etc.
2. **Herramientas de diseño**: Photoshop, Figma, GIMP mantienen historial de acciones
3. **Terminales**: bash mantiene historial de comandos con flechas arriba/abajo
4. **Bases de datos**: transacciones con rollback/commit usan principios similares

### 🏗️ Paso 1: Análisis de la lógica
**Análisis del problema:** Se mantienen dos pilas: una de acciones realizadas y otra de acciones deshechas. Al hacer undo, la acción actual pasa a la pila de redo. Al hacer una acción nueva, se vacía la pila de redo. **Edge cases:** undo sin acciones (null), redo sin acciones (null), add después de undo descarta redo.

### ⚙️ Paso 2: Implementación
**Implementación:** Clase Historial con métodos: add(accion), undo(), redo(). Usar dos listas como pilas (append/pop). El estado actual se reconstruye concatenando la pila de acciones.

### 🚀 Paso 3: Complejidad y Optimización

**Complejidad temporal:** O(1) por operación  
**Complejidad espacial:** O(n)

```python
class Historial:
    def __init__(self):
        self.acciones = []
        self.deshacer = []

    def add(self, accion):
        self.acciones.append(accion)
        self.deshacer = []

    def undo(self):
        if self.acciones:
            self.deshacer.append(self.acciones.pop())
            return ''.join(self.acciones)
        return None

    def redo(self):
        if self.deshacer:
            self.acciones.append(self.deshacer.pop())
            return ''.join(self.acciones)
        return None
```

```java
import java.util.*;

public class Historial {
    private List<String> acciones = new ArrayList<>();
    private List<String> deshacer = new ArrayList<>();

    public void add(String accion) {
        acciones.add(accion);
        deshacer.clear();
    }

    public String undo() {
        if (acciones.isEmpty()) return null;
        deshacer.add(acciones.remove(acciones.size() - 1));
        StringBuilder sb = new StringBuilder();
        for (String a : acciones) sb.append(a);
        return sb.toString();
    }

    public String redo() {
        if (deshacer.isEmpty()) return null;
        acciones.add(deshacer.remove(deshacer.size() - 1));
        StringBuilder sb = new StringBuilder();
        for (String a : acciones) sb.append(a);
        return sb.toString();
    }
}
```
